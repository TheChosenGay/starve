# 碰撞检测可视化（Go → WebAssembly）

把 [`pkg/collide`](../../pkg/collide) 编译成 WebAssembly 在浏览器里跑，用于开发期自测，不依赖 C# 客户端。

页面：

- `index.html` — 基础图元：拖拽图形，实时看 Go 算出的最近点 / 距离 / 重叠（点–线段、点–三角形、点–OBB、胶囊–胶囊、球–AABB、球–OBB）。
- `scenes.html` — 命中判定场景：子弹射击（球扫掠一组 AABB/胶囊，命中处标红）、劈砍（**刀是 OBB**，按角度细分扫掠，命中胶囊身体）、劈砍隔墙（刀先砍在墙上，目标不受影响）。
- `sim.html` — 压力测试：几百个球在盒子里受重力下落、互相碰撞，接触点短暂标红，看复杂情况下碰撞检测是否稳定。
- `swing.html` — 挥砍扇形：一次挥击 = 一个扇形查询体积（角度区间 + 距离带），命中时返回**命中部位**，在目标身上画局部红色。
- `arena.html` — 竖劈竞技场：所有角色都在走（目标漫游、玩家追击最近目标），玩家手上有刀，**点击画面挥砍**；
  这次是**竖直劈砍**（弧线在竖直平面里，绕「竖直 × 朝向」轴张开），命中处同样返回部位并画红块。
- `broad.html` — 宽阶段压测：同一批物体、同一批查询，**三种实现并排对比**——不用宽阶段 / 数组扫描器（O(N)）/ BVH 扫描器（O(log N)），给出盒子测试次数、形状测试次数与引擎内耗时，并可切换索引的增量更新 / 每帧全量重建。
- `blast.html` — 丢炸弹：**点画面把炸弹丢到鼠标指的地面位置**，引信到点爆炸，**爆炸半径内的胶囊全部闪红并按接触信息炸飞**（闪红/力度 = 穿透深度 ÷ 半径，方向 = 爆心 → 目标，抬升 = 接触点高度；命中者离地翻滚、落地回正）。

## 用法

```bash
make wasm-collide     # 编译 web/collide/collide.wasm 并拷贝 wasm_exec.js
make serve-collide    # 起本地 http 服务（默认 8099）
```

然后浏览器打开 <http://localhost:8099/>（命中场景 `/scenes.html`、掉落压测 `/sim.html`、
挥砍扇形 `/swing.html`、宽阶段压测 `/broad.html`、竖劈竞技场 `/arena.html`、
丢炸弹 `/blast.html`）。

> WASM 必须经 HTTP 加载，直接双击 `index.html`（file://）不行。

## 交互（基础图元页）

- 顶部按钮切换用例：点–线段 / 点–三角形 / 胶囊–胶囊 / 球–AABB
- 在画布上拖动红点移动对象（平面 x/z），滑杆调高度（y）
- 黄色点是由 Go 计算出的最近点，虚线是最近点连线
- 左下角 HUD 显示重叠状态与距离
- 拖空白处旋转 · 滚轮缩放 · 拖红点移动对象 · 滑杆调高度

## 交互（压力测试页）

- 滑杆调物体数量（10–300）与弹性，按钮重置
- 拖空白处旋转、滚轮缩放
- 红色圆点是本帧的接触位置，会短暂显示后淡出

## 交互（挥砍扇形页）

- 滑杆调张角 / 射程 / 内圈；「刀身」切换是否画当前刀刃
- 挥砍过程中，扇形从起始角张开到当前刀刃角，被扫到的目标立刻在**命中部位**出现红块
- 命中部位来自引擎返回的 `Point`（目标表面朝向扇心的点），可直接用于特效 / 贴花 / 击退
- HUD 显示候选数（宽阶段剔除后）、本次命中数、每个命中目标的命中点坐标

## 交互（宽阶段压测页）

- 滑杆调物体数（200–80000）、每帧查询数、移动比例；「索引」在增量更新与每帧全量重建之间切换
- 每帧先把同一批查询分别喂给三种实现：不用宽阶段（全部物体直接算形状）、数组扫描器（线性剔除）、BVH 扫描器（动态 AABB 树）；每次调用在 Go 侧重复跑 10 轮取平均
- 可视化：灰点 = 被宽阶段剔除 · 蓝点 = 进了窄阶段（外面那个蓝框就是它的 fat AABB）·
  红点 = 真的命中 · 黄色粗圈 = 首个查询球、虚线方框 = 它的 AABB · 其余细黄圈 = 本批其它查询
- HUD 先讲清楚"每帧在做什么"，再给每次查询 / 合计的形状测试次数、耗时、相对加速比与索引维护耗时

### 这里的压测逻辑

每帧做两件事：

1. **推进模拟**：让「移动比例」那么多物体沿各自方向走一小步（撞墙反弹），把新图元同步进引擎
   （增量 `Update`，或切换成「每帧全量重建」走 `Rebuild`）。
2. **同一批查询各跑一遍两种模式**：每次查询是**一个半径 1.6 的球**，问「谁和我重叠」。
   查询位置由 `(seed, tick, i)` 哈希得到，两种模式拿到的是**完全相同的查询**，对比才公平。

| 模式 | 每次查询做什么 | 盒子测试 | 形状测试 |
|---|---|---|---|
| 不用宽阶段 | 把 N 个物体**全部**喂给 `TestShapes(球, 胶囊)` | 0 | N × 查询数 |
| 数组扫描器 | 线性过一遍全部盒子，只有候选进形状测试 | N × 查询数 | 候选数 |
| BVH 扫描器 | 从树根往下，只走与查询盒相交的子树 | ~log N 个节点 + 相交子树 | 候选数 |

所以测的是：**在命中结果完全一致的前提下，盒子测试与形状测试各被调用了多少次、花了多少时间**。
"结果一致"不是嘴上说的——`cmd/collidewasm/broad_test.go` 里逐帧对拍三种模式的命中数。

实测（20000 物体 / 32 查询 / 每帧移动 20%）：

```
不用扫描器    形状测试 640,000                    130.9 ms
数组扫描器    盒子测试 640,000  形状测试 1,948     11.9 ms
BVH 扫描器    盒子测试   9,308  形状测试 1,948      0.80 ms   ← 比数组快 15×，比不用宽阶段快 164×
```

## 交互（竖劈竞技场页）

- **点一下画面 = 挥砍**（拖动画布 = 转视角，滚轮缩放；空格也可以挥砍）
- 滑杆调张角 / 射程 / 内圈 / 厚度；「追击」切换玩家是否追最近的目标，「自动挥砍」让它自己砍
- 目标会漫游（撞墙反弹），玩家转身面向最近目标并追到 1.4 米处停下——每帧都在 `Update` 引擎
- 命中时在目标身上留下局部红块，红块跟着目标移动（存的是相对目标的位置）
- HUD 显示挥砍进度与当前刀角、候选数、本次命中、命中率与每个命中点的坐标
- 也可以直接用 `arena.html?auto=1` 打开自动挥砍模式

## 交互（命中场景页）

- 顶部切换三种场景；「重放」重跑当前场景
- 子弹交给 Go 的 `collideCast`（球扫掠 AABB / 胶囊）；劈砍交给 `collideSwing`（刀是 OBB，按角度细分做旋转扫掠）
- 左下角 HUD 显示命中目标、接触点、沿运动比例 t 与距离

## 交互（丢炸弹页）

- **点一下画面 = 把炸弹丢到鼠标指的地面位置**（拖动 = 转视角，滚轮缩放，空格也可以丢）
- 鼠标指到哪，黄圈/黄球线框就跟到哪：落点由 Go 用 `IntersectRayAABB` 打一块厚地面板算出来，
  HUD 同时给出这个圈里的**宽阶段候选数**
- 滑杆调爆炸**半径 / 引信 / 击退力度**；「自动投弹」让它自己往目标头上丢（也可以 `blast.html?auto=1`）
- 演示 / 截图链接可以带参数：`?auto=1&radius=5&fuse=0.05&power=12&steps=22`
  （`steps` = 开局先空跑 N 帧，这样一打开就是"刚炸完"的画面）
- 引信走完才爆：飞行中的炸弹画成抛物线，带一个随时间变短变红的引信环
- 爆炸瞬间贴地扩散一圈冲击波，**半径内的胶囊全部闪红**（越近越红，会随时间衰减回橙色），
  同时被**炸飞**：离地飞出一道抛物线、在空中翻滚，落地小弹一下再站回原位
- 炸飞的每一份数据都来自这一次碰撞查询的返回值（不是另算的一套）：

  | 结果 | 来自 | 说明 |
  |---|---|---|
  | 闪红强度 / 击飞力度 | `Result.Depth` ÷ 半径 | 擦边炸 ≈ 0，贴脸炸 = 1（穿透 ≥ 一个半径） |
  | 击飞方向 | 爆心 → 目标骨架点 | 正压在爆心上时退化成"顺着投掷方向推开" |
  | 起飞高度 | `Result.Point` 的高度 | 接触点越靠脚 → 是在脚下炸的 → 飞得越高、翻得越狠 |

- 高度是**真的进了碰撞查询**：飞在空中的目标，胶囊图元的 A/B 也跟着抬高，
  于是同一颗地面炸弹对它的穿透会明显变浅（HUD 的"在空中 N 个"就是在数这个）
- HUD 显示爆炸次数、命中人次、此刻闪红个数与在空中个数，以及上一次爆炸每个命中目标的
  **穿透深度**、**闪红强度**与**起飞速度**（都是碰撞查询的返回值）
- 这一页验证的是「一块几何决定一批结果」：同一个爆心，谁闪红、闪多红、被炸多高多远，
  都由那一次 `Engine.Overlap(Sphere)` 的结果推出来

## 说明

- `collide.wasm` 与 `wasm_exec.js` 是构建产物，已在 `.gitignore` 中排除。
- 基础页：场景以 JSON 传给 Go 的 `collideEval`，结果以 JSON 返回。
- 命中场景页：子弹走 `collideCast`（`SweepSphereAABB` / `SweepSphereCapsule`）；劈砍走 `collideSwing`（`ContactOBBOBB` / `ContactCapsuleOBB`，角区间细分为保守前进）。
- 挥砍扇形页：场景走 `collideSectorSetup`（把玩家与目标注册进 `collide.Engine`），每帧走 `collideSectorStep`（扇形查询 + 返回命中部位）。
- 竖劈竞技场页：`collideArenaSetup` 建场景、`collideArenaStep` 推进一帧（漫游 + 追击 + 同步图元进引擎）、`collideArenaSwing` 做竖直劈砍查询（旋转轴由引擎按玩家朝向算，前端只给角度区间与射程）。
- 宽阶段压测页：`collideBPSetup` 建场景（N 个胶囊注册进引擎）、`collideBPStep` 推进一帧（增量更新或全量重建索引）、`collideBPQuery` 按模式跑一批查询。
- 丢炸弹页：`collideBlastSetup` 建场景（目标注册进引擎）、`collideBlastAim` 把鼠标射线打到地面上（顺带数宽阶段候选）、
  `collideBlastThrow` 投一颗（落点同一套射线算法 + 引信）、`collideBlastStep` 推进一帧
  （漫游 / 炸飞后的抛物线 / 翻滚 / 闪红衰减 / 引信倒计时 / `Overlap(Sphere)` 结算爆炸）。
- 压力测试页：整场景每帧交给 Go 的 `collideSim` 步进一次（积分 → 平面约束 → 两两碰撞），碰撞判定全部走 `pkg/collide`。
- 坐标系：右手系，x 右 / z 上（俯视平面），y 为高度。
