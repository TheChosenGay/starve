# starve 项目规划方案

> 状态：v0.1（初版规划）
> 依据：《游戏服务器设计-Actor与ECS.md》（v0.5 方案讨论稿）
> 目标：自研核心四件套（Actor、ECS、Cluster、Gateway），其余（玩法、存档、客户端工具等）由 AI 基于核心接口实现。

## 1. 项目概述

starve 是一个饥荒（Don't Starve）类生存游戏的服务器。架构分层与设计文档一致：

```text
Gateway(连接/协议)        Cluster(跨节点寻址/RPC)
        \                    /
         \                  /
          Actor(并发与所有权边界)
                   |
                ECS(模拟内核)
```

- 一个世界（房间）= 一个 world actor + 一个 ECS World；
- 客户端只连 Gateway（pomelo 协议），Gateway 通过 Actor 寻址投递消息，不直接碰 ECS；
- 单机 MVP 网关与世界同 engine（本地 PID 直连），跨节点是 M6（Cluster）阶段的事。

## 2. 已锁定的技术基线（摘自设计文档 §2/§7）

| 层 | 选择 |
|----|------|
| Actor 内核 | hollywood 风格：ringbuffer 邮箱 + 按需 goroutine + 批处理、类型化消息、崩溃缓冲 + 重启、PID 寻址、kind 激活 |
| ECS | 自研：稀疏集 + 泛型查询 + 惰性注册表（§4.3 原理） |
| 客户端协议 | pomelo（握手/心跳/route/request/notify/response/push），实现蓝本 = cherry `net/parser/pomelo` |
| 服务器间通信 | hollywood remote/cluster（dRPC，类型化 protobuf），**不走 pomelo** |
| Gateway | 自研：pomelo parser + agent/session + 路由注册表 |
| 确定性 | L1 固定系统顺序 + L2 种子化随机；**不做 L3 lockstep** |

关键纪律（所有里程碑必须遵守）：

1. ECS 系统是纯函数：不调 actor API、不发网络消息，副作用只走 outbox；
2. 随机数一律从 `world.Resource[RNG]` 取，禁止全局 `rand` 与系统内 `time.Now()`；
3. tick 内禁止同步跨 actor 调用；world actor 执行超时默认 300ms（可配置）；
4. 路由与消息类型契约定义在共享 protobuf，客户端/服务端复用同一套 proto。

## 3. 里程碑总览

| 里程碑 | 名称 | 核心产出 | 完成标志 |
|--------|------|----------|----------|
| M0 | 工程初始化 | 仓库骨架 + CI | `go build/test` 通过，目录结构就位 |
| M1 | ECS 内核 | 稀疏集 + World + 泛型查询 + 惰性注册表 | 确定性测试通过，饥荒组件可跑 |
| M2 | Actor 内核 | hollywood 风格运行时 | 崩溃重启 / 批处理 / Request 测试通过 |
| M3 | Actor ↔ ECS 接缝 | WorldActor（命令缓冲 + outbox + 10Hz tick） | 纯函数纪律测试通过 |
| M4 | Gateway 最小闭环 | WS + pomelo + agent + 路由注册表 | 两个客户端互见移动 |
| M5 | 玩法系统 | 饥饿 / 昼夜 / 生长 / 伤害 / 存档 | 可玩闭环 + 存档回放一致 |
| M6 | Cluster | dRPC + kind 激活 + 服务发现 | 多节点跨节点寻址可用 |

依赖关系：

```text
M0 ─→ M1 ─→ M3 ─→ M4 ─→ M5
 └──→ M2 ──→ M3
                 └──────→ M6（Stage 3，需要时才启动）
```

## 4. 分阶段任务拆解

### M0 工程初始化

- [x] 初始化 Go module（占位 `starve`）；
- [x] 建立 §5 目录结构；
- [x] 工程规范：Makefile（`make test` / `make lint` / `make build`），lint 未安装时降级 `go vet`；
- [x] 初始化 git 仓库并提交首个 commit；
- 验收：`make test && make lint` 通过，空骨架可构建。

> 完成于 2026-08-04。

### M1 ECS 内核

- [x] 稀疏集 `sparseSet[T]`：`Add` / `Get` / `Has` / `Remove`（交换删除）、`dense` + `sparse` + `entities` 三数组；
- [x] `World`：`CreateEntity` / `DestroyEntity`，实体 ID 密集分配 + 空闲列表复用；
- [x] 泛型组件 API：`Add[T]` / `Get[T]` / `Has[T]` / `Remove[T]`（包级泛型函数，见 §9 决策记录）；
- [x] 惰性注册表：`map[reflect.Type]存储`，第一次使用才创建（§4.3.3）；
- [x] 查询：`Query[T]` / `Query2[A, B]`（遍历较小集合 + sparse 反查）；
- [x] `System` 接口 + 固定顺序注册 `AddSystem(order, s)`；
- [x] `Resource`：`AddResource` / `Resource[T]`（世界时钟、RNG 收进 Resource）；
- [x] 事件队列 + dirty：组件增删/实体销毁走事件队列（tick 内消费）；`MarkDirty` / `DrainDirty`（另加确定性 `DrainDirtySorted`）供快照消费；
- [x] 组件元数据注册表（名称 + 编解码器），为存档/快照/配表共用；
- [x] 确定性测试：同样的操作序列产生同样的结果；禁止 map 迭代；
- 验收：饥荒示例组件（Position / Health / Hunger）可建实体、加组件、Query 遍历；确定性测试 + 基准测试通过。

> 完成于 2026-08-04。基准（Apple M4 Pro）：稀疏集 Add ≈ 5.3ns、Get ≈ 1.3ns，1 万实体全量 Query ≈ 7.6µs/op，0 分配。

### M2 Actor 内核

- `PID`（address + id），如 `world/room-1`；
- ringbuffer 有界邮箱 + 按需 goroutine + 批处理（默认 300 条/轮），空闲 actor 零成本；
- 类型化分发：`Receive(ctx)` + `switch msg := ctx.Message().(type)`，无反射；
- `Engine`：`Spawn`（kind 激活）/ `Send` / `Request(timeout)` / `Respond` / `BroadcastEvent`；
- 崩溃缓冲（panic 不丢消息）+ 自动重启（maxRestarts）+ 子 actor 监督清理；
- 定时器 `SendRepeat`；
- 同步调用 `Request`：超时丢弃迟到回复；
- 验收：panic 不丢消息、重启后继续服务、超时语义正确；tick 内同步跨 actor 调用被测试拦截。

### M3 Actor ↔ ECS 接缝

- `WorldActor`：持有 `sim *ecs.World`、`commands []Command`、`outbox []Effect`；
- `onAction` 只入命令缓冲，不立即执行；
- `onTick` 三阶段：`ApplyCommands` → `RunSystems(dt)` → `flushOutbox`；
- 10Hz 固定 dt（100ms），世界时钟 = tickCount × dt，存档恢复时从存档读取；
- 副作用经 outbox 表达（`Emit(Push{...})` / `Emit(SendMessage{...})`），由 actor 统一 drain；
- 验收：消息到达速率与模拟速率解耦；系统纯函数测试（不触碰 actor API / 网络）。

### M4 Gateway 最小闭环（MVP 目标）

- WS 连接器（TCP 二期，协议编解码同一套）；
- pomelo package/message 编解码：握手 / ack / 心跳 / 数据 / 踢线；flag、mid varint、route 字典（dict 压缩二期，先移植 cherry 的 dict/protos）；
- agent actor（每连接一个，ID 即 SID）：单写者写队列、读 goroutine → `PacketReceived`、生命周期状态机 Init → WaitAck → Working → Closed；
- 路由注册表：`route → MsgType → TargetRule`（固定 PID / kind / 按 UID 查）；反序列化在网关做，世界 actor 收已解码的类型化消息；
- mid 关联：request 进来记 mid，响应自带上下文（uid + mid），不维护 pending 表；
- 会话表：`UID ↔ agent PID`，绑定/解绑；同 UID 重复登录踢旧连接；断线通知世界 actor 走离线保护；
- 登录时序：握手保持纯净（版本/心跳协商），连接后 `login` 请求校验 token；
- 最小闭环：WS 连接 + world actor 10Hz tick + 玩家移动 + 广播位置；
- 测试客户端（命令行或网页）用于联调；
- 验收：两个客户端连接、登录、移动，互相看到位置推送。

### M5 玩法系统（AI 并行轨，接口就绪即启动）

- 饥饿系统（Hunger）、昼夜系统（时钟 Resource + 光照）、生长系统（Growable）；
- 伤害/砍伐系统（Position + Health）；
- 实体离线保护（断线保留 N 分钟）；
- 存档/快照：遍历组件元数据表序列化，存档恢复后确定性一致；
- 验收：单机可玩一圈饥荒生存闭环；回放/存档测试一致。

### M6 Cluster（Stage 3，需要时再细化）

- dRPC 传输 + 类型化 protobuf（服务器间不走 pomelo）；
- kind 激活（分布式拉起 actor）；
- 服务发现：zeroconf / Consul；
- 网关 ↔ 世界节点跨节点寻址；
- 验收：多节点部署，gateway 可跨节点路由到 world actor。

## 7. 玩法系统编写规范（dt 与 System）

给所有（含 AI 编写的）玩法系统定的规矩，M5 起强制执行。

### dt：固定步长，由 actor 注入

- 时间一律由 actor 在每个 tick 注入（M3 起 10Hz → 100ms），系统内**禁止** `time.Now()` 与全局 `rand`（设计文档 §5.2 纪律 3）。
- dt 实际是常量，系统可以只按"每 tick 一次"写；dt 参数的意义是显式化"时间在流动"，将来做暂停 / 慢放 / 回放快进时不用改接口。
- 世界时钟 = tickCount × dt，存档恢复时从存档读取，不重新计时。

### System 的实例化形态

- **一个系统一个 struct**：零字段或少量配置字段，注册一次、长驻复用，不是每 tick 新建：

```go
type HungerSystem struct{ Rate int } // 配置字段，创建时定好

func (s *HungerSystem) Update(w *ecs.World, dt time.Duration) {
    ecs.Query[Hunger](w, func(e ecs.Entity, h *Hunger) {
        h.Level -= s.Rate // 固定 dt 下可只按 tick 计
    })
}

w.AddSystem(OrderSim, &HungerSystem{Rate: 2})
```

- **系统尽量无状态**（只留配置字段）：需要跨 tick 的状态放组件或 Resource，不放系统字段——系统实例是共享单例，字段会变成隐式全局状态，破坏确定性。
- **order 按阶段常量填**：阶段常量在 `internal/game` 统一定义（如 10=输入 / 100=模拟 / 1000=结算），玩法代码里不散落魔法数字；约定见 §4 M1 `AddSystem` 注释。
- 系统是纯函数：不调 actor API、不发网络消息，副作用只走 outbox（M3 接缝）。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| actor 内核自研复杂度高 | M2 延期 | MVP 裁剪：不做消息池/零分配，批处理默认值先用 300 |
| pomelo SDK 兼容（dict/protos 压缩） | M4 协议对接延期 | MVP 用标准 protobuf 编码，dict 压缩二期移植 cherry 实现 |
| 玩法迭代破坏确定性 | M5 回放/存档回归 | L1/L2 纪律写入测试，确定性测试作为 CI 门禁 |
| Cluster 复杂度蔓延 | M6 范围失控 | 单机 MVP 明确不引入跨节点；M6 前不做跨节点设计实现 |

## 9. 决策记录

所有技术决策见《游戏服务器设计-Actor与ECS.md》§7「已定决策汇总」；本方案只负责把它们落成分期计划与任务清单。后续新增决策（如 module 路径、存档格式、玩法范围）在此文档追加。

- 2026-08-04：**Gateway 复用评估**——不整体依赖 `~/feeds` 的 comet（自定义帧协议与 pomelo 不兼容，且 import 会拖入整模块依赖）；以其连接层骨架（单写者写泵 / ConnManager / 协议无关 Core）为 `internal/gateway` 实现蓝本。详见 [gateway-comet复用评估.md](gateway-comet复用评估.md)。
- 2026-08-04：**Go 泛型 API 形态**——Go 不支持泛型方法，设计草案 §4.5 的 `w.Add[T]` / `w.Query[T]` 以包级泛型函数实现（`ecs.Add[T](w, e, c)`、`ecs.Get[T](w, e)`、`ecs.Query[T](w, fn)`、`ecs.Query2[A, B](w, fn)`），类型安全不变，仅调用形态变化。
