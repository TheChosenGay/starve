# P0.2 质量门禁与可观测性

> 状态：已实现（2026-08-19）  
> 基线：从 `optimize/p01-client-experience-review` 创建的 `feature/p0.2-quality-gates`

## 目标

把 P0.1 文档中的工程约束变成可执行门禁，并先建立低成本、可替换的观测接口。P0.2 不引入具体监控后端，也不改变 ECS 的确定性规则。

## 统一门禁

服务端唯一完整入口：

```bash
make check
```

它依次执行：

1. `gofmt` 只读检查；
2. `go mod tidy -diff` 依赖一致性检查；
3. protobuf 生成代码漂移检查；
4. `go build ./...`；
5. `go test -race ./...`；
6. `golangci-lint`，未安装时使用 `go vet`；
7. `go run ./cmd/configcheck` 验证生产配置。

`.github/workflows/quality.yml` 在 push 和 pull request 上执行同一入口，避免 CI 和本地规则分叉。

## 配置门禁

- `cmd/configcheck` 只加载配置，不启动 Actor 或监听端口。
- Gateway 启动配置失败时立即退出，不再带着部分配置运行。
- `MapPath` 启用时，`map.json` 中的手摆资源和工作站是唯一事实源；legacy `resources.json`、`stations.json` 不再覆盖有效地图配置。
- 地图加载会校验出生点、资源、工作站、掉落、生物、效果、发射器和散布规则的类型、数值与边界。
- `QueryConfig` 返回的工作站坐标与世界实际生成坐标一致。

## 依赖与认证边界

服务端已移除指向本机目录的 feeds `replace`。Gateway 依赖稳定的 `TokenValidator` 接口，默认实现使用与账号服务一致的 HS256 JWT 和 `JWT_SECRET`。

这解决了两个问题：

- CI 和其他开发机不再依赖 `/Users/.../feeds/pkg`；
- 后续接入远程账号服务时只需新增适配器，不修改登录业务流程。

## 协议门禁

- 服务端 `scripts/check_generated_proto.sh` 在临时目录重新生成 Go protobuf，并与仓库产物比较。
- 客户端门禁直接比较两端 `game.proto`、`message.proto` 和路由常量。
- 鱼人和蜥蜴枚举已同步到服务端协议，仅做稳定 ID 预留，不代表服务端 AI 已实现。

跨仓库合并顺序：服务端协议变更先合入并通过 CI，客户端随后同步。客户端 CI 从 `TheChosenGay/starve` 获取权威协议。

## 最小可观测性

`WorldActor` 只依赖 `TickObserver` 抽象，并在 tick 结束报告：

- `world_id`
- `tick`
- `duration_ms`
- `commands`
- `dirty_entities`
- `removed_entities`
- `effects`

默认 `SlogTickObserver` 对超过 tick 预算的执行记录 warning，正常 tick 按配置间隔记录 debug。观测器不进入 ECS，不影响存档和回放。

环境变量：

- `GATE_TICK_LOG_INTERVAL`：正常 tick 采样间隔，默认 20 tick。

## 后续

P0.3 可在现有 `TickObserver` 后接 OpenTelemetry/Prometheus 适配器，并补 Actor 邮箱、连接数、命令拒绝和快照字节数。该阶段不应让业务层直接依赖具体监控 SDK。
