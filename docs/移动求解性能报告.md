# 移动求解性能报告

> 生成方式：`go test -run TestPerfReport -v ./internal/game/systems/`
> 场景：2000 个静态障碍（每 3 格一棵，模拟森林）+ 规则分布的移动体
> 预算：50ms / tick（服务端 20Hz）

## 结论速览

| 指标 | 数值 |
|---|---|
| 1000 移动体整 tick | **3.76 ms（OrcaAOI）/ 10.10 ms（BVH）** |
| 预算占比 | **7.5% / 20.2%** |
| OrcaAOI 相对 BVH | **快 45~64%** |
| ORCA 纯求解 | **242 ns / 次（16 邻居），0 分配** |
| 缩放 | 固定密度下**线性**（每实体 7.4~10.0 µs） |

**1000 实体只占 7.5% 预算**，按线性外推正常密度可支撑上万个实体。

## 表 1：整 tick 耗时（两种邻居来源）

| 场景 | 平均邻居 | BVH | OrcaAOI | 省 |
|---|---|---|---|---|
| 200 实体·间距4 | 16.9 | 1.85 ms | **0.66 ms** | 64% |
| 1000 实体·间距4 | 18.6 | 10.10 ms | **3.76 ms** | 63% |
| 2000 实体·间距4 | 19.0 | 17.22 ms | **7.85 ms** | 54% |
| 1000 实体·间距2（密） | 70.8 | 26.97 ms | **13.74 ms** | 49% |
| 4000 实体·间距4 | 19.3 | 29.69 ms | **16.44 ms** | 45% |

**邻居来源是当前最大的一档收益**：实体越多、越密，OrcaAOI 的优势越明显
（因为它把"找候选"的宽阶段从 BVH 遍历换成按格读取）。

## 表 2：阶段占比（1000 实体，BVH 路径）

| 阶段 | 耗时 | 占比 |
|---|---|---|
| ① desired（意图位移） | 0.023 ms | 0.2% |
| ② slide（静态滑掠） | 0.537 ms | 5.3% |
| ③ avoid（邻居 + ORCA + 提交） | 9.621 ms | **94.5%** |
| 合计 | 10.180 ms | |

**ORCA 求解本身只占 3%**（约 0.3ms）。③ 里的 9.3ms 是：

- 邻居收集：BVH 4.6ms / OrcaAOI 2.8ms
- 组装 `ORCABody` + `ApplyDisplacement` + `MarkDirty`：约 5ms

## 表 3：缩放（固定密度扩数量）

| 实体数 | 平均邻居 | 耗时 | 每实体 |

| 250 | 17.3 | 2.26 ms | 9.02 µs |

**每实体成本恒定 ~7~10 µs**，说明是**线性**缩放 O(N)——
邻居数不随总量增长（固定密度），验证了"地图上限不受实体数限制"。

## 已修的严重性能 bug

### `FilterStatic` 每次调用重建 map（本次报告前修复）

```go
// 错误写法：SlideStatic 每实体每 tick 调一次，这里就重建一次
dynSet := make(map[Handle]struct{}, len(c.dynHandles))
for _, h := range c.dynHandles { dynSet[h] = struct{}{} }
```

实测（1000 动态体）：

```
1000× FilterStatic（仅构造过滤器）:  17.06 ms
1000× SlideStatic（完整）:            17.11 ms
→ 99.7% 花在构造过滤器上，几何扫掠只有 0.05ms
```

修法：惰性维护 `dynHandleSet`，构造 O(1)。

**整 tick 效果：24.5ms → 6.6ms（BVH）/ 4.3ms（OrcaAOI）**

### 邻居表降频缓存（已实现但缺省关闭）

实测是**负优化**：非刷新 tick 要逐邻居回查 ECS，比索引一次返回完整结构更贵。
1000 实体 27.9ms → 37.3ms。缺省设为 1（不降频）。

## 现状与后续

**当前瓶颈**：③ avoid 里的"邻居收集 + 组装 + 提交"（约 9ms / 10ms，BVH 路径）。
换成 OrcaAOI 后这一项降到约 6ms。

**剩余优化空间**（按性价比）：

1. **缺省切到 OrcaAOI** —— 白拿 45~64%，零风险（行为逐位一致）
2. **组装环节**：逐邻居读 `Moveable`/算半径 —— OrcaAOI 已缓存，BVH 路径还可优化
3. **`ApplyDisplacement` + `MarkDirty`**：逐实体的格子层提交

**不建议继续投入的方向**：

- 邻居表降频（实测负优化）
- 静态滑掠缓存（只占 5.3%，且是硬约束，缓存会引入穿模）
- ORCA 求解优化（只占 3%）

## 测量方法说明

- 单轮 benchmark 波动可达 **20%**（22.1~27.4ms），本报告全部用**多轮取中位数**
- 曾两次因测量错误得出错误结论：
  1. 用"两只相向"的简单场景测降频 → 两家一开始就在彼此半径内，测不出失效模式
  2. 逐系统计时没喂移动意图 → `MoveSystem` 空转，测出 0.3ms（实际 24ms）
- 教训：**先精确测量，再提优化方案**
