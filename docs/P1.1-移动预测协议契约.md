# P1.1 移动预测协议契约

## 目标

锁定服务端权威移动与客户端预测之间的最小稳定契约，覆盖重连、重复/迟到输入、
服务端 tick、输入确认和两端碰撞公式一致性。P1.1 不把伤害、采集或制作结果交给客户端。

## 协议

- 握手声明 `protocol_version=1.1`，能力包含 `input_epoch_ack`、`snapshot_tick`、
  `effective_move_speed`。
- 登录成功后服务端分配非零 `input_epoch`。同 UID 重连会获得新 epoch，旧连接被踢。
- `PlayerMove` 携带 `(input_epoch, seq)`；seq 在单个 epoch 内从 1 单调递增。
- `Snapshot` / `SnapshotDelta` 携带 `(tick, input_epoch, last_accepted_seq)`。
- `Moveable.effective_speed` 是地块/状态效果修正后的权威速度；客户端预测不得使用基础
  `speed` 替代，否则雪地减速会持续产生回拉。
- ACK 只在移动命令通过世代、顺序、实体所有权和位置组件校验后推进。
- 同 epoch 下 `seq <= last_accepted_seq` 的重复或迟到输入丢弃；不同 epoch 的输入丢弃。
- 服务端仍临时接受 `(epoch=0, seq=0)` 的旧客户端移动，但它不参与 ACK。

`tick` 是世界固定步长计数，不是墙钟时间。`last_accepted_seq` 只代表服务端接受了该方向
意图，不代表客户端预测位置正确，位置仍以快照为准。

## 客户端预测

移动命令表达“持续方向”，不是逐帧位移。因此客户端不重放一长串历史位移：

1. `OwnMovementSim` 按当前本地意图和服务端相同的 `effective_speed × dt`、对角归一化、
   `stepAxis` 与可走性规则推进；
2. 收到权威位置时按误差软校正/硬跳，当前本地意图保持；
3. 旧 epoch 或倒退 tick 的增量帧不应用；
4. 未确认移动超过 4 条时暂停继续预测，防止断网时无限领先；ACK 追上后恢复。

服务端与客户端共享 `testdata/movement_golden.json`。客户端质量门禁同时检查文件同步，
Go/C# 测试分别执行同一组负方向、对角归一化、贴墙和沿墙滑动向量。

## 边界

- 动态实体阻挡仍以服务端快照为准；客户端只对已知阻挡做预测。
- 攻击、制作、采集只预测动画/进度展示，不预测权威结果。
- WebSocket 本身有序可靠；重复、旧世代、倒退 tick 测试用于覆盖重连与应用层重试，
  不是模拟 UDP。

## 验收

服务端：

```bash
make check
```

客户端：

```bash
make check
STARVE_GATE_URL=ws://127.0.0.1:8081/ws make e2e
```

`ProtocolSmoke` 会验证握手能力、全量快照 epoch、移动后 ACK 追平和停止确认。
