# M7 生物系统：客户端对接文档

> 范围：客户端把服务端生物（Creature）渲染出来并接入交互。协议无新增路由——
> 攻击/拾取复用现有 `world.player.attack` / `world.player.pickup`。

## 1. 快照里新增的组件

生物实体 = `Position + Health + Moveable + AOI + Creature + AI + Weapon`（快照均可读）：

| 组件 | 字段 | 客户端用途 |
| --- | --- | --- |
| `Creature` | `kind`、`threats`、`home_x/y`、`roam_radius`、`drops` | 渲染哪种生物；掉落提示 |
| `AI` | `state`（0=idle 1=chase 2=attack 3=flee）、`target`、`flee_hp`、`last_hit_by/at`、`hostile_players`、`hostile_kinds` | 状态机 → 动画；血条旁的状态提示 |
| `Weapon` | `attack_range/damage/cooldown` | 可选：显示攻击范围 |
| `AOI` | `radius`、`visible`（**仅 debug 模式编码**） | `GATE_DEBUG_AOI=true` 时画感知圈/视野线 |
| `Health` | `cur/max` | 血条 |

`CreatureKind` 枚举（`game_pb.ts` 里 `CreatureKind.RABBIT/WOLF/BOAR/DEER/SPIDER`）：

| kind | 表现 | 行为 |
| --- | --- | --- |
| RABBIT 兔子 | 小、棕色 | 被动，被打会逃跑；掉肉 ×1 |
| WOLF 狼 | 灰、中等 | 主动猎兔/玩家；掉肉 ×2 |
| BOAR 野猪 | 深棕、大 | 高血量近战，主动；掉肉 ×3 |
| DEER 鹿 | 白/褐、大 | 被动，低血逃跑；掉肉 ×2 |
| SPIDER 蜘蛛 | 小、紫黑 | 低血量快速，主动；掉肉 ×1 |

## 2. 渲染建议

1. **按 kind 给外观**：每个 kind 一张贴图/骨架动画（尺寸建议：兔子/蜘蛛 < 玩家，狼 ≈ 玩家，野猪/鹿 > 玩家）；没有贴图时先用颜色块区分（参考颜色）。
2. **状态机 → 动画**：`AI.state` 直接映射动作——`idle` 待机/游荡、`chase` 跑步、`attack` 攻击前摇/挥击、`flee` 逃跑（更慌张/更快）。
3. **血条**：有 `Creature` 的实体画血条（`Health.cur/max`）；非满血才显示。
4. **受击反馈**：`Health` 变化时可做闪白/飘字；`AI.last_hit_by` 可用于"谁打了它"的提示（可选）。
5. **掉落**：生物死亡 → 实体挂 `Loot`（肉），按现有掉落物渲染 + 拾取。
6. **地图变大**：`configs/map.json` 已从 80×80 扩到 **128×128**（出生点移到 64,64），相机/缩放建议适配更大视野；`MapConfig` 结构不变，渲染逻辑不用改。

## 3. 交互（无新协议）

- 玩家攻击生物：复用 `world.player.attack`（target_entity = 生物实体 id）；服务端统一走 `ApplyAttack`（扣血 + 受击标记 + 仇恨 + 打断）。
- 拾取掉落：复用 `world.player.pickup`。
- 客户端无需感知 AI 细节，只看 `state` 做表现。

## 4. 调试

- 服务端 `GATE_DEBUG_AOI=true`：每只生物快照带 `AOI.visible`（当前视野内的实体 id），可画感知圈/连线。
- `GATE_AOI_INTERVAL`（默认 4）可调感知刷新频率。

## 5. 服务端对照

- 组件/系统：`components/creature.go`、`components/ai.go`、`components/weapon.go`、`components/aoi.go`、
  `systems/ai_system.go`、`systems/aoi_system.go`、`worldmap/walkgrid.go`（A* 寻路）。
- 配置：`configs/creatures.json`（模板）、`configs/map.json`（handplaced.creatures 手摆出生）。

## 6. 建筑（Building）

### 6.1 契约摘要

- 快照组件 `"Building"`：`kind`（CAMPFIRE=火堆 / WALL=木墙）、`width × height`（占格尺寸）、`placed`。
  `placed=false` 时无 Position（蓝图/物品态，可渲染半透明预览）；`placed=true` 后带 Position，
  并挂 `Block` 组件（占格已写入服务端 `MapData` 阻挡层，阻挡移动/寻路）。
- 配置：`configs/buildings.json`（建筑模板：kind → name / width / height），
  登录后随 `world.config` 的 `buildings` 列表推送（客户端幽灵预览按 kind 查尺寸）。
- 命令：
  - `world.build`（request）：`Build{kind}` → `BuildResponse{ok, entity, message}` ——
    **只创建未放置**的建筑实体，响应里的 `entity` 是后续 Place/BuildCheck 引用的实体 id；
  - `world.build.check`（request）：`BuildCheck{entity,x,y}` → `BuildCheckResponse{ok}` —— 查询该建筑能否放到坐标；
  - `world.place`（notify）：`Place{entity,x,y}` —— 放置（火堆挂 `HeatSource` 供暖/降雾，占格阻挡）；
  - `world.demolish`（notify）：`Demolish{target_entity}` —— 拆除（取消阻挡并销毁实体）。
  - 执行者不限于玩家（Boss/角色等也可用），网关填入当前会话实体。

### 6.2 交互时序（客户端实现顺序）

1. **建**：点建造 → `world.build`（request，带 `kind`）→ 收到 `BuildResponse`：
   - `ok=true`：拿到 `entity`，进入幽灵预览模式；此时快照里已有一个
     `Building{placed=false}`（无 Position）实体，客户端应把它渲染为半透明预览；
   - `ok=false`：`message` 为原因（`player dead` = 幽灵不能建造、`player not found` 等），弹出提示。
2. **查**：预览跟随鼠标/摇杆移动 → 按 `world.config.buildings` 里该 kind 的
   `width × height` 画占格范围，发 `world.build.check`（request）问服务端能否放；
   **节流**：拖动时每几个 tick 发一次（建议 ~100ms），不要每帧发；服务端只校验地形/建筑占格。
3. **放**：确认位置 → `world.place`（notify，带 `entity,x,y`）。
   服务端会再次校验占格，失败则静默忽略（客户端可等下一帧快照：实体仍是 `placed=false`，
   预览不消失，提示"放不下"）。成功则快照里该实体变为 `placed=true + Position`。
4. **拆**：对已放置建筑发 `world.demolish`（notify，带 `target_entity`）→ 实体销毁，占格恢复。

### 6.3 客户端适配清单

- [ ] `world.config` 解析 `buildings` 列表，建 `kind → {width, height}` 查询表；
- [ ] `world.build` 请求/响应封装（带超时与错误提示）；
- [ ] 幽灵预览：半透明渲染 + 按 `width×height` 画占格网格 + 绿/红态（`build.check` 驱动）；
- [ ] `world.build.check` 节流（~100ms 一次，拖动停止后发最后一次）；
- [ ] `world.place` / `world.demolish` notify 封装；
- [ ] 快照 `Building` 组件渲染：`placed=false` 预览态 / `placed=true` 静态实体（火堆建议带火光粒子）；
- [ ] 交互限制：玩家自己处于死亡（幽灵）状态时禁用建造入口（服务端会拒绝）。

### 6.4 边界情况

- **失败不丢流程**：`build.check` 返回 `ok=false` 只是"当前位置放不下"，预览继续跟随，
  换位置再查；只有 `world.build` 失败才退出预览。
- **2×2 占格**：火堆模板是 2×2，`place` 的坐标是**左上角锚点**，服务端校验并阻挡
  `(x..x+1, y..y+1)` 四格；拆除时四格一起恢复。
- **多实体预览**：同时只保留一个未放置建筑；再次 `world.build` 前建议先 `place` 或等服务端
  销毁旧预览实体（当前 MVP 未做取消接口，客户端可本地丢弃预览态实体）。
- **渲染建议**：按 `kind` 出贴图（火堆/木墙），`width×height` 决定占格范围；放置后是静态实体。

## 7. 交互系统（能力 / 装备 / 攻击）客户端适配

> 服务端把"采集/砍伐/挖掘/攻击"统一成**主动能力（-er）↔ 受激能力（-able）**交互模型，
> 并把装备改为实体槽位。**输入路由全部不变**，客户端主要是快照组件名的变化。

### 7.1 快照组件变更

| 旧组件（已下线） | 新组件 | 字段 | 说明 |
| --- | --- | --- | --- |
| `Workable` | `Choppable` / `Minable` / `Pickable` | `kind, work_left, max_work` | 树/矿/浆果按动作挂对应受激能力；增量快照组件名变了 |
| `Equipped` | `Equip` | `head, hand, body`（uint64 实体 id） | 玩家三槽位，不再存 kind；手持要反查实体 |
| `Weapon` | `Attacker` | `attack_damage, attack_range, attack_cooldown` | 生物/玩家裸手都有（裸手 = 默认值） |
| `Health` | `Health` | 新增 `defense_percent` | 攻击减免百分比（装备叠加） |
| — | `Respawnable` | `ticks, ticks_left` | 可重生资源（浆果）：采空后倒计时恢复 |
| — | `Defense` | `percent` | 护甲实体携带（游戏暂无护甲物品，协议已就绪） |

### 7.2 行为变化（渲染/交互建议）

- **徒手只能采集和攻击**：玩家快照没挂 `Chopper`/`Miner` 能力时，砍树/挖矿按钮建议置灰；
  采集（`Picker`）和攻击（`Attacker`）是裸手默认能力，永远可用。
- **看手持**：`Equip.hand` 是工具实体 id；要显示"手里拿什么"，从快照反查该实体（挂 `Chopper`
  是斧头、`Miner` 是镐），或直接用玩家身上复制的主动能力组件。
- **防御/攻击展示（可选）**：`Health.defense_percent` 可渲染护甲值；`Attacker.attack_range/cooldown`
  可画攻击范围/冷却条。攻击伤害、减免全部服务端结算，客户端不参与计算。
- **采集进度**：资源耐久读 `Choppable/Minable/Pickable.work_left`（原 `Workable.work_left` 位置不变）。

### 7.3 输入路由（不变）

`world.player.gather` / `chop` / `mine` / `attack` / `equip` 全部照旧：采集/砍/挖/攻击都是
`{ target_entity }`，装备是 `{ kind }`（kind=0 卸下）。客户端不需要为攻击传属性。
