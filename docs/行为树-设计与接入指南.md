# 行为树（Behavior Tree）：设计与接入指南

> 范围：把 AI 的"做什么"从 `AISystem` 的硬编码 4 状态 switch 拆出来，
> 变成可组合的节点树。本篇讲清**为什么这么设计**、**怎么加新行为**、
> **怎么调试**，以及踩过的坑。

## 1. 为什么要行为树

改造前 `AISystem.tickAI` 里的决策是一段 switch：

```go
switch {
case target == 0:              ai.State = CreatureIdle
case 无攻击力 || 低血:          ai.State = CreatureFlee
case 在攻击范围:                ai.State = CreatureAttack
default:                       ai.State = CreatureChase
}
```

问题不是"跑不起来"，而是**加需求必须改这段 switch**：

- 狼低血时先跑回狼群再反击
- 白天躲洞里、晚上才出来猎食
- 看见玩家先呼救，2 秒后才扑上去

这些迟早会把 switch 变成互相纠缠的 `if`。行为树把决策拆成**小节点**，
用**树形结构**组合——加需求是"加一个节点"，不是"改一段逻辑"。

## 2. 核心模型

每 tick 从**根节点**开始执行，自顶向下传播，节点返回三态：

| 返回值 | 含义 |
| --- | --- |
| `Success` | 做成了 |
| `Failure` | 做不了 |
| `Running` | 正在做、还没完（下 tick **继续**，不重头开始） |

`Running` 是行为树区别于普通决策表的关键：它让"挥刀 8 tick 前摇"这类
**跨 tick 动作**能自然表达——动作自己记住进度，树只负责"还在做"。

### 节点分类

| 类别 | 节点 | 语义 |
| --- | --- | --- |
| 组合 | `Sequence` | 依次执行，**全成功才成功，遇失败即中断**（"走过去→再攻击"） |
| 组合 | `Selector` | 依次尝试，**一个成功就成功**（替代 switch 的核心） |
| 装饰 | `Inverter` | Success ↔ Failure 取反 |
| 装饰 | `Succeeder` | 恒返回 Success（可选行为不打断 Sequence） |
| 装饰 | `Cooldown` | N tick 内最多执行一次（攻击冷却） |
| 条件 | `HasTarget` / `LowHP` / `CanAttack` / `InAttackRange` / `OutOfRoam` | 只读黑板，无副作用 |
| 动作 | `AttackAction` / `ChaseAction` / `FleeAction` / `ReturnHomeAction` / `WanderAction` / `IdleAction` | 提交控制意图 |

## 3. 内置树

### 掠食者（`PredatorTree`：狼 / 野猪 / 蜘蛛）

```
Selector
├── Sequence  逃跑：低血 → flee
├── Sequence  攻击：有目标 + 在范围 → attack（Cooldown 装饰器节流）
├── Sequence  追击：有目标 → chase
└── Selector  兜底
    ├── Sequence  超出游荡半径 → 回防出生点
    └── 游荡
```

读法：从上往下试，**第一个能做的赢**。这与改造前的 switch 优先级一一对应。

### 被动生物（`PreyTree`：兔 / 鹿）

```
Selector
├── Sequence  有威胁 → flee（被动生物不还手，不等血量阈值）
└── Selector  兜底：回防 / 游荡
```

差别在逃跑条件：掠食者看**血量**，被动生物看**有没有目标**
（对应原逻辑 `AttackDamage <= 0 || 低血`）。

## 4. 代码结构

```
internal/game/behavior/          ← 纯行为树运行时（不依赖 ECS，可独立单测）
├── node.go                       Node 接口 / Status / TickContext
├── blackboard.go                 Blackboard + Env + NodeStateStore 接口
├── composite.go                  Sequence / Selector / Inverter / Succeeder / Cooldown
├── leaf.go                       条件与动作叶子
├── tree.go                       Tree（id 分配 + 校验 + Reset + Describe）
├── state.go                      MemoryState（测试用运行态）
├── creature_tree.go              内置树：Predator / Prey / Dormant
└── node_test.go                  节点语义单测

internal/game/components/behavior_tree.go   ← 组件（运行态 + proto codec）
internal/game/systems/behavior_bridge.go     ← 黑板/Env 的 ECS 实现
internal/game/systems/behavior_runtime.go    ← 树缓存 + 实体绑定
```

### 为什么桥接层在 systems 而不是 components

`components` 不能 import `interactive`（会成环：`interactive` 已 import
`components`）。桥接要读 `interactive.Attacker`（玩家手里的武器），而
`systems` 本来就依赖两者——与 `AISystem.weaponOf` 的做法一致。

行为树本体因此**完全不感知 ECS**，可以脱离世界单测（见 `node_test.go`）。

## 5. 运行态与存档

树**定义**是静态的（同类生物共享，按 kind 缓存在世界 Resource 里）；
每个实体只存自己的**运行态**：

| 状态 | 用途 | 存储 |
| --- | --- | --- |
| Running 游标 | 记录组合节点正在跑第几个子节点 | `BehaviorTree.RunningChild` |
| 计数器 | `Cooldown` 剩余 tick | `BehaviorTree.Counters` |

两者都进快照/存档——否则读档后 AI 会从树根重新决策、行为突变。

`NodeID` 在构建时按**深度优先顺序**分配，只要构建顺序不变 id 就稳定
（`TestAssignIDsAreStableAndUnique` 守住这条）。`map` 遍历顺序随机，
所以编码前一律排序。

## 6. 怎么加新行为

### 加一个条件或动作

1. 在 `leaf.go` 加一个内嵌 `nodeBase` 的结构体，实现 `Tick` / `Children`；
2. 需要新数据 → 给 `Blackboard` 加方法，并在 `btBoard` 里实现；
3. 需要新副作用 → 给 `Env` 加方法，并在 `btEnv` 里实现；
4. 加进 `creature_tree.go` 里对应的树。

**注意**：节点实例不可跨树共享（`NewTree` 会 panic 检测重复挂载），
因为 id 是写回节点里的。

### 加一整棵新树

1. 在 `behavior` 包写 `XxxTree()` 工厂；
2. 在 `game.proto` 的 `BehaviorTreeKind` 加枚举值，重新生成：
   `protoc --go_out=. --go_opt=paths=source_relative pkg/proto/game/game.proto`
3. 在 `components.TreeKindByName` 与 `components.TreeOf` 各加一行；
4. 配置里写 `"behavior_tree": "xxx"`。

## 7. 配置

`configs/creatures.json` 可选字段 `behavior_tree`：

```json
{
  "kind": "wolf",
  "attack_damage": 8,
  "behavior_tree": "predator"
}
```

留空则按 `attack_damage > 0` 推断（掠食者 / 被动）。
非法值 fail fast（避免"配错了却静默用默认树"）。

## 8. 调试

```go
tree := components.TreeOf(components.TreeKindPredator)
fmt.Println(tree.Describe())   // 打印树结构 + 每个节点的 id
```

`Describe()` 会输出 "类型#节点id" 的缩进树，对照 `BehaviorTree.RunningChild`
就能看出"当前卡在哪个节点"。

## 9. 踩过的坑（回归测试守住）

### 9.1 测试差点测不到新代码

`AISystem` 在实体没有 `BehaviorTree` 组件时**回退到旧状态机**（为兼容旧存档）。
而测试用的 `addWolf` 起初不挂行为树 —— 于是"生物测试全绿"实际测的是回退路径，
行为树的 bug 被完全掩盖。加 `addBehaviorTree` helper 后才真正覆盖。

> 教训：**回退路径会让新代码"假绿"**。有兼容分支时，测试必须显式选择分支。

### 9.2 攻击冷却不再递减（真实回归）

原实现的冷却递减藏在 `attack()` 里，而 `attack()` 只在走攻击分支时被调用。
决策换成行为树后 `attack()` 不再执行 → `AI.Cooldown` 永远不归零 →
**生物打完一下就再也不攻击**。

修法：把递减提到 `runTree` 里每 tick 统一维护。
`TestBehaviorTreeAttackCooldownCountsDown` 守住这条。

> 教训：迁移逻辑时，**"顺带发生的副作用"最容易漏**——递减写在动作函数里，
> 看起来像动作的一部分，实际是每 tick 的状态维护。

## 11. 后续

- **群体仇恨**：在 `Env` 加 `ShoutForHelp()`、加 `ShoutAction` 节点，
  被攻击时广播给半径内同伴（计划中的下一个玩法）。
- **配置驱动树**：若要策划配表，在 `behavior` 包加一个 JSON 解析器
  把节点名映射到工厂函数——框架本身不用动。
