# 集群运行与验证（大厅 + 世界服务 + 服务中心 + NATS）

把 starve 拆成「大厅（HTTP + actor engine，注册进集群）+ 世界服务器节点（NodeManager + 共享 combet 网关）+ 服务中心（NATS 版 ServiceCenter）」。

## 启动

```bash
docker compose up --build -d
docker compose logs -f
```

服务：

| 服务 | 入口 | 地址 |
|---|---|---|
| `nats` | NATS 控制面 | 127.0.0.1:4222 |
| `registry` | 集群服务中心（控制面） | — |
| `lobby` | HTTP 大厅 | http://localhost:8080 |
| `world` | 世界节点（WS 网关 + NodeManager） | ws://localhost:8081/ws |

## 验证一：大厅创建世界

```bash
curl -s -X POST http://localhost:8080/rooms
```

返回形如：

```json
{"room_name":"room-1","access_token":"<hex>","world_addr":"world:8082"}
```

拿到 `access_token`。这一步验证：大厅（集群成员）→ 世界节点 NodeManager（跨节点集群消息 `CreateWorld`）→ 子化一个 WorldActor 并登记 `access_token`。

## 验证二：玩家连到指定世界并游玩

用 `access_token` 连世界节点的 WS 网关：

```bash
go run ./tools/pomelo-client \
  -addr ws://localhost:8081/ws \
  -access "<access_token>" \
  -uid 42 -move 1,0 -interval 500ms
```

流程：握手（携带 `access_token`）→ 登录（在对应世界创建玩家）→ 发移动 → 打印世界推送/快照。

`tools/pomelo-client` 的 `-access` 会把 `access_token` 放进握手 payload，网关的 `OnHandshake` 用 `NodeManager.QueryToken` 解析到具体世界，绑定 `connID→worldPID`，后续命令经 `engine.Send(该世界, Command)` 路由到对应 `WorldActor`。

## 常见

- 每个世界的存档按房间名存：`<saveRoot>/<roomName>.bin`（容器里 `/data/worlds/<roomName>.bin`）。
- 再开一个客户端、用 `-move` 看是否能在同一世界里互相看到（双客户端验收）。
