# P0.1 真实基线与架构决策

> 状态：已固化（2026-08-19）  
> 目的：让代码、客户端和文档共享同一套可验证事实；后续设计以本文件和 ADR 为准，不再以早期里程碑描述推断现状。

## 1. 当前可运行基线

- 服务端：Go，入口为 `cmd/gate`；Gateway 与 WorldActor 当前运行在同一进程、同一 Actor Engine。
- 客户端：Godot 4.7.1 .NET / C#，独立仓库 `starve-godot`。
- 网络：WebSocket + pomelo；路由和消息体由 protobuf 定义。
- 模拟：单个 WorldActor 独占一个 ECS World，固定 50ms 步长（20Hz）。
- 地图：默认 `configs/map.json`，128×128，种子化生成；出生点为 `(64,64)`。
- 移动：服务端权威，连续速度默认 10 格/秒；客户端做同公式预测和快照校正。
- 已有闭环：登录、移动、AOI、采集、战斗、背包、装备、制作、建造、睡眠、昼夜、天气、存档和输入日志回放。
- 睡眠是营火附近的个人持续动作：每 100 tick 恢复 2 点生命并额外消耗 2 点饥饿，随后在同一 ActionState 上自动开始下一周期；不快进世界时间，正常昼夜与饥饿 tick 继续运行。移动、实际受伤、死亡、主动取消或营火失效会中断且不产生额外收益。
- 尚未纳入生产基线：Cluster、多世界跨节点调度、正式账号与部署流水线。

验收命令：

```bash
make build
make test
make lint
```

客户端验收：

dotnet test ../starve-godot/Starve.Core.Tests/Starve.Core.Tests.csproj

## 2. 稳定边界

### Gateway

只负责连接、pomelo 编解码、鉴权、会话、路由和请求应答。Gateway 不直接读写 ECS 组件；所有世界状态变化都投递给 WorldActor。

### WorldActor

是 Actor 与 ECS 的唯一接缝，拥有 ECS World、命令缓冲、固定 tick、存档和副作用 outbox。tick 内禁止等待其他 Actor 或网络 I/O。

### ECS

只负责确定性模拟。系统顺序固定；随机数来自世界资源中的种子 RNG；系统不调用网络或 Actor API。业务可预期失败在命令边界返回稳定错误码，基础设施错误继续上抛或记入结构化日志。

### 客户端

`Starve.Protocol` 负责协议，`Starve.Core` 负责可测试的纯逻辑，`GodotClient/Game` 负责输入和渲染。客户端预测不改变服务端权威结果。

依赖方向固定为：

```text
Godot 渲染 → Core / Protocol
Gateway → Actor 消息契约
WorldActor → ECS
ECS → 无上层依赖
```

禁止反向依赖和 Gateway/ECS 直连。

## 3. 时间与坐标契约

- 服务端模拟步长：50ms；所有玩法倒计时使用 tick，不使用系统墙钟推进。
- 世界位置：`Position{X,Y}` 是整数锚点；`Moveable{SubX,SubY}` 是 `[0,1)` 子格偏移。
- 实际渲染位置：`Position + Sub`。
- 移动顺序：先 X 后 Y；对角速度除以 `sqrt(2)`；跨格前查询目标格；阻挡时正向贴 `0.999`、负向贴 `0.001`。
- 停止命令：方向归零，服务端将子格落定到锚点；客户端等待服务端确认并校正。
- 工作站距离：以整数锚点计算曼哈顿距离，当前阈值为 3 格。
- 视角旋转只属于客户端显示坐标，不改变世界坐标、移动方向或服务端判定。

这些规则修改时，必须同时更新服务端移动测试、客户端 `OwnMovementSim` 测试和本文件。

## 4. 配置单一事实源

- `configs/map.json`：启用 `MapPath` 时，负责地图规格、出生点、手摆资源/工作站/生物和散布规则。
- `configs/stations.json` 与 `configs/resources.json`：仅在未启用 `MapPath` 的兼容/测试路径使用，不得与运行中的地图配置混合解释。
- `configs/crafting.json`：配方、材料、产物、耗时和工作站要求。
- `configs/resource_templates.json`：物品与资源模板、堆叠、工具、掉落和阻挡属性。
- `configs/buildings.json`：可建造建筑模板。

客户端工作站提示必须来自服务端快照中的真实 `Workstation + Position`，不得读取另一份坐标配置。制作能否开始最终由服务端判断。

## 5. 变更策略

- 高频变化：天气、AI、掉落、配方选择等通过策略接口或配置注册。
- 中频变化：网络库、存储、认证、资源加载通过适配器隔离。
- 低频稳定机制：ECS 存储、Actor 所有权、pomelo framing 可直接实现，但公开接口必须保持稳定。
- 每个新增系统只承担一种模拟职责；跨系统协作通过组件、事件或资源，不直接互调具体实现。
- 可预期业务失败返回稳定错误码；未知异常不得被吞掉。

## 6. 日志、指标与验收缺口

P0.1 先固定观测字段；P0.2 落地 `make check` / CI 与观测接口；P0.3 接入 OTel/Prometheus 与本机 Grafana。

- 日志公共字段：`world_id`、`tick`、`uid`、`entity_id`、`route`、`command`、`error_code`、`duration_ms`。
- 核心指标：tick 耗时和超时数、Actor 邮箱深度、连接数、网关拒绝数、快照字节数、存档耗时、客户端校正距离。
- 不记录 token、完整存档或玩家隐私数据。

服务端合并门槛是 `make check`。客户端是 `make check`，在线协议 E2E 走独立的 `make e2e`。P0 工程基线到此收口；WorldActor 拆分与 10Hz/20Hz 同世界时间一致性延后，不阻塞 P1。

## 7. 决策记录

1. 服务端权威、客户端预测；不采用客户端权威移动。
2. 单 WorldActor 独占 ECS；不允许多个 Actor 并发修改同一世界。
3. 配置在进程启动时加载并 fail fast；运行期暂不热更新。
4. MapPath 存在时 `map.json` 是实体种子坐标的唯一事实源。
5. 制作按钮允许发起请求，客户端校验只做提示，服务端错误必须展示给玩家。
6. 相机围绕跟随目标旋转，旋转通过客户端 Pivot 场景层实现，不污染世界坐标。

任何推翻上述决定的变更，应先在本节增加“替代原因、迁移方式、兼容影响”，再修改代码。
